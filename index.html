Haltpoint: getting started

Haltpoint is a command-line tool for flashing, debugging and diagnosing ARM Cortex-M and RISC-V microcontrollers through the debug probes you already have: SEGGER J-Link, ST-Link and CMSIS-DAP. Its doctor command checks each step between your computer and the chip, and explains in plain words what's wrong and how to fix it.

This guide is for version 0.2.0.

Preview: J-Link with SAM4E. Haltpoint supports J-Link probes and the SAM4E family, but we haven't yet verified this combination on our own bench. Please tell us what works and what doesn't. A copy of haltpoint doctor output is the most useful thing you can send.

1. Install

Download the file for your system from the list below. Each comes with a .sha256 file, so you can check the download with shasum -a 256 -c FILE.sha256 (macOS) or sha256sum -c FILE.sha256 (Linux).

macOS, Apple silicon haltpoint-v0.2.0-aarch64-apple-darwin.tar.gz Unpack it and put haltpoint on your PATH, e.g. /usr/local/bin.
macOS, Intel haltpoint-v0.2.0-x86_64-apple-darwin.tar.gz The same.

2. First connection: J-Link and SAM4E

  1. Connect the J-Link to the board's SWD header and power the board. A SAM-ICE works too, since it is a J-Link for Microchip SAM parts.

  2. Check that haltpoint sees the probe:

    haltpoint list

  3. Run the connection check, naming your chip:

    haltpoint doctor --chip ATSAM4E16E

    haltpoint chips sam4e lists the SAM4E names it knows: ATSAM4E16C, ATSAM4E16E, ATSAM4E8C and ATSAM4E8E. Doctor checks the probe, the target voltage, the SWD link at falling speeds, and the chip itself. Then it tells you what's wrong and how to fix it.

    If the chip's security bit is set, doctor reports that the chip is locked. The only way to unlock it is a full erase, which destroys the firmware on it, so haltpoint never erases unless you ask it to (see haltpoint erase below).

  4. Save your settings, so you don't repeat them. Put a haltpoint.toml at the root of your firmware project (haltpoint looks in the current folder and its parents):

    chip = "ATSAM4E16E"
# Optional:
# probe = "1366:0101"        # VID:PID[:SERIAL] when several probes are connected
# speed_khz = 1000           # if doctor says the link needs a lower speed
# connect_under_reset = true # if doctor says the chip only answers under reset

3. Everyday commands

Command What it does
haltpoint flash app.elf Writes firmware, verifies it and restarts the chip. Takes ELF, Intel HEX, or a raw .bin with --base 0x00400000 (the SAM4E flash start).
haltpoint reset Resets the chip and lets it run. --halt stops it at the first instruction.
haltpoint rtt --elf app.elf Shows what the firmware prints over SEGGER RTT, and sends lines you type back to it. --log FILE, --grep TEXT and --timestamps help with long sessions.
haltpoint swo --clock-hz 120000000 Shows ITM/SWO output. Pass your firmware's core clock.
haltpoint gdb A GDB server on localhost:1337 for arm-none-eabi-gdb or VS Code.
haltpoint vscode build/app.elf Writes a VS Code (Cortex-Debug) setup, so F5 flashes and debugs.
haltpoint erase --yes Erases the whole flash, destroying the firmware.
haltpoint ui A page in your browser to list probes, run doctor, flash, erase, reset and watch RTT.

Every command takes --help.

4. Using haltpoint from AI coding assistants and scripts

Haltpoint is a plain command-line tool with predictable exit codes, so an AI assistant (or a script, or CI) can drive it the same way you do.

  • Exit codes. Every command exits 0 on success and non-zero on failure. haltpoint doctor exits 1 if any check failed. haltpoint test exits 0 when the test passed, 1 when it failed, and 2 if neither result arrived in time.

  • Hardware tests in one command. haltpoint test flashes test firmware, watches its RTT output for a pass or fail line, and exits with the result:

    haltpoint test build/tests.elf --pass "ALL TESTS PASSED" --fail FAIL --timeout 60 \
    --junit results.xml --log test.log

    --junit writes a JUnit XML report that CI systems display, and --log keeps the full output for the assistant to read afterwards.

  • Bounded runs. haltpoint rtt --seconds 10 --log out.log stops by itself, so an assistant doesn't hang waiting on a terminal that never closes.

  • Diagnosis an assistant can act on. haltpoint doctor prints each finding with its fix as plain text, which assistants read well. A JSON form (haltpoint doctor --json) is coming in the next release.

  • Keep the board's settings in haltpoint.toml. Then the assistant only runs haltpoint flash, haltpoint test and so on, without guessing chip names or probe IDs.

  • Destructive commands need an explicit flag. haltpoint erase refuses to run without --yes. Review any assistant's request to add it.

5. When something goes wrong

Run haltpoint doctor first, and send us its full output along with:

  • your system, and haltpoint --version,
  • the probe (J-Link model, or SAM-ICE) and the board,
  • the command you ran and what happened.
